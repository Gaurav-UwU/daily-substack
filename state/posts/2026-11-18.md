## The hidden sensor in plain sight

When I opened MissionControlAggregator.dll in Binary Ninja I expected to find a benign performance monitor. Instead I saw a list of executable names, codex.exe, claude.exe, copilot.exe, cursor.exe, alongside classic dev tools like python.exe and dotnet.exe.

The DLL isn’t a compiler helper; it is a matcher that watches for those binaries, flips a bit, and later ships the bitmap to Windows Diagnostics. It runs silently in the background, collecting only the presence of the executables.

## How the telemetry works

Because optional diagnostic data is enabled by default, the report lands on Microsoft’s servers unless a user explicitly opts out. The data is sent as part of the standard Windows Diagnostics payload.

The feature is called CLICodingAgentUsage, feature ID 62580080. Four slots watch for CLI agents (copilot.exe, claude.exe, codex.exe, agy.exe) and five slots watch for desktop agents (github.exe, claude.exe, codex.exe, cursor.exe, antigravity.exe).

A second set of twelve broader categories captures traditional tools, node.exe, gcc.exe, clang.exe, gdb.exe, javac.exe, devenv.exe, code.exe, and more. Each match sets a bit; the ETW event Segments.SubCohorts later emits a compact bitset that says only which agents were observed, not how long they ran or what code they generated.

## Why product teams should care

Each match sets a bit; the ETW event Segments.SubCohorts later emits a compact bitset that says only which agents were observed, not how long they ran or what code they generated. This limited granularity still provides Microsoft with a clear picture of which AI coding assistants are gaining traction. Product teams can use this insight to anticipate shifts in developer tooling and adjust their roadmaps accordingly.
