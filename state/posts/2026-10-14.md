## The Numbers That Matter

Harvard researchers Fiona Chen and James Stratton analyzed 300 million work events from Jellyfish, covering more than 700 000 engineers at 700 firms. When a company added AI coding agents, total lines of code rose 30 percent, commits climbed 20 percent and pull requests increased 23 percent. Yet the resolution rate for Jira‑tracked issues and epics stayed flat, with no statistically significant change.

The same study found the average review time ballooned 49 percent after agents arrived. Pull requests that needed changes nearly doubled, and comments per pull request grew 35 percent. In response, the share of workers doing code reviews rose 14 percent, but overall employment levels remained unchanged.

Even though 80 percent of firms used AI‑assisted code review by March 2026, AI agents contributed only 23.3 percent of review comments and 10.8 percent of pull requests. Humans still shoulder the bulk of the review burden.

## Why Review Became the New Bottleneck

AI agents excel at generating syntactically correct patches, but they lack awareness of a codebase’s architectural constraints. The extra code forces reviewers to spend more time reconciling style, dependencies and design intent. That extra friction erodes the time saved during the coding phase.

Parsimony, a benchmark that measures net coding units added, shows that models that add more code also tend to solve more tasks, but the added units increase maintenance overhead. The metric subtracts deleted code, highlighting that many AI‑generated patches are later trimmed back, a symptom of misaligned output.

The result is a classic production line problem: a faster upstream machine (the AI agent) feeds a slower downstream station (human review). Until the downstream station speeds up, the line’s overall throughput cannot improve.

## From Raw Code to Shippable Product

A pull request is not a product feature; it is a piece of raw material that must be shaped, tested and integrated. Without a clear gate that ties code changes to business outcomes, teams end up with more commits but no additional shipped value.

Agent37, a YC‑backed sandbox for running agents, illustrates the missing piece. It offers low‑cost, isolated environments where generated code can be exercised against integration tests before reaching the main repo. Teams that adopt such sandboxes can catch mismatches early, reducing the review load downstream.

The missing link is a value‑focused pipeline that treats AI output like any other artifact: lint, test, verify against feature specifications, then only merge if it moves a KPI forward. Without that gate, the code simply accumulates.

## What PMs Must Do Today

1. **Define a clear acceptance metric** for every AI‑generated change. Tie pull requests to a Jira epic or OKR so reviewers can ask, “Does this move the needle?”

2. **Automate the first line of defense** with sandboxed test runners such as Agent37. Run integration and regression suites automatically on every AI patch before it lands in the main branch.

3. **Limit net code growth** by adopting a Parsimony‑style policy: reject patches that add more than a calibrated amount of net units without proportional test coverage.

4. **Reallocate reviewer capacity** toward architectural alignment rather than syntax fixes. Use the 14 percent increase in reviewers as a signal to formalize a “design review” stage separate from the line‑by‑line code review.

5. **Track feature velocity** independently of commit volume. If the number of resolved Jira epics does not rise after AI adoption, double‑check the integration steps.

When PMs treat AI‑generated code as raw material rather than a finished product, the hidden bottleneck shifts from the model to the process. The next wave of productivity will come not from bigger models but from tighter governance, smarter pipelines and a relentless focus on shipped value.
