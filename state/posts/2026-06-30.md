Ten weeks ago, Gusto launched a new AI product called Cofounder. No Figma. No Jira. No specs. No roadmap. No standups. Just five people, one perma-Zoom room, and Claude Code doing the work.

This wasn’t a prototype. It shipped to paying customers. It handles payroll workflows. It talks to Mindbody and other HR systems. It’s live. And it was built without a single product manager.

Most teams would need three months just to agree on what to build. Gusto’s team skipped that. They didn’t write a spec. They didn’t wireframe a screen. They didn’t create a backlog. They didn’t wait for approval.

Instead, they used what they called the trash-can method. Write code. Ship it. Get feedback. Delete it if it’s wrong. No review meetings. No stakeholder alignment sessions. Just a live agent in Claude Code, running evals against real customer data, fixing bugs as they emerged.

One of the five was a designer with no engineering background. She learned to write code by pairing with Claude Code. Within weeks, she was shipping at the 94th percentile of the team’s velocity. Not because she was gifted, because the tool did the heavy lifting. She told Claude: "Make this button bigger. Make it respond when the user types. Show the error in red." And it did. Not perfectly. But enough to test. Then it iterated. Then it shipped.

The stack? Claude Code as the product engine. Cloudflare Workers for deployment. Vercel AI SDK to connect the frontend. Wispr Flow to turn voice notes into prompts. OpenClaw to auto-generate evals from customer Slack messages. No project management tool. No design tool. No documentation repo. The only artifact was the code itself, and even that was rewritten daily.

The perma-Zoom room replaced every meeting. Not as a video call. As a persistent, always-on workspace. Everyone stayed in it. The designer would say, "I need the payroll flow to handle overtime." Claude Code would start coding. The engineer would say, "That won’t work with the Mindbody API." Claude Code would pull the API docs, test the endpoint, and rewrite it. No Slack threads. No Notion docs. No Jira tickets. Just a stream of code, evals, and voice prompts.

The key insight? AI isn’t automating tasks. It’s replacing the entire coordination layer.

For decades, we’ve treated product development as a relay race: PM writes specs → designer makes mocks → engineer builds → QA tests → launch. Each handoff needed tools: Jira to track, Figma to align, Confluence to document. Those tools weren’t just aids, they were the scaffolding holding the whole process together.

Gusto burned the scaffolding. And the building didn’t fall. It got faster.

The bottleneck isn’t engineering speed anymore. It’s human coordination. The time spent aligning, reviewing, approving, explaining, and documenting. Claude Code doesn’t need a PRD. It doesn’t need a roadmap. It needs a prompt and a live eval.

This is organizational rearchitecture, not automation.

You can’t copy this by adopting Claude Code. You have to kill the processes that made you need Figma and Jira in the first place.

Most teams will try to keep their tools and add AI as a plugin. They’ll say, "Let’s use AI to write Jira tickets." Or, "Let’s auto-generate Figma specs." That’s like putting a jet engine on a horse cart and calling it innovation.

The real move is to ask: What if we didn’t need the cart at all?

Gusto’s team didn’t have time to build a product org. They had time to build a product. And they did it by removing every layer between idea and execution.

What does this mean for you?

If you’re a PM: stop writing specs. Start writing prompts. Your job isn’t to translate vision into tickets. It’s to define the right evals, the real customer problems that need solving. The agent will do the rest.

If you’re an engineer: your leverage isn’t in your coding speed. It’s in your ability to teach an agent what good looks like. The best engineers now aren’t the ones who write the most code. They’re the ones who write the cleanest evals.

If you’re a founder: the next great product won’t be built by a 10-person team with 3 tools. It’ll be built by a 3-person team with one agent and a perma-Zoom room.

The future of product isn’t better tools. It’s fewer humans trying to manage them.

The question isn’t whether your team can use AI to ship faster.

It’s whether you’re brave enough to delete the whole stack and start over.
