## The Incident in Detail

When we pointed our autonomous hacking agent, Strix, at *.baseten.co, we expected a routine scan. Within 25 minutes the tool reported a live GitHub personal access token (PAT) belonging to the account **basetenbot**. The token granted admin and push rights to Baseten’s main product repo, the GitOps repo that drives their clusters, their Homebrew tap, and read/write access to private customer repositories.

The token lived in the build history of a Docker image called `baseten/baseten-app`. The image was stored in a public Harbor registry at `gcp-us-east4-zlw.registry.baseten.co`. Strix could list the project, pull the image anonymously, and inspect the config layer where the token was embedded in a `RUN` command. The token dated back to March 2023 and still worked when we discovered it in July 2026.

Baseten’s security team confirmed the breach as critical, locked down the registry project and rotated the token by the next afternoon. Their response was swift, but the damage was already exposed: a malicious actor could have rewritten production code, exfiltrated data, or poisoned future model releases.

The episode has already sparked a heated discussion on Hacker News, making it the freshest concrete example of supply‑chain risk in AI‑first SaaS products. It highlights how quickly such vulnerabilities can become public.

## Why Traditional Threat Models Miss This

Most AI platform threat models focus on the model layer: data poisoning, prompt injection, inference leakage. The Baseten case proves that the real attack surface often lies in the dev‑ops pipelines we hand to customers. By exposing a PAT, the platform handed an LLM‑powered agent unrestricted write access to the very code that powers the service.

A PAT is a single point of failure. If it is stored in a Docker image config, cleaning up the filesystem does not erase it. The token survives in build metadata, which is downloadable alongside the image. This is a classic secret‑scanning blind spot that many teams overlook.

Supply‑chain attacks have long haunted traditional software, but AI platforms amplify the impact. An attacker who can modify the GitOps repo can change the container images that run inference, inject malicious code into model serving pipelines, or swap out model binaries. The downstream effect is not just a data breach; it is a potential integrity breach of every downstream product that consumes the model.

The lesson is that security cannot be an after‑thought feature toggle. It must be baked into the core product architecture, just like scaling or latency.

## Building a Zero Trust DevOps Layer

Zero trust for AI platforms starts with token hygiene. Every PAT that a platform generates for a customer‑facing agent should be scoped to the minimum required permissions and have an expiration date. Short‑lived tokens eliminate the window for abuse.

Second, the build pipeline must run in an isolated sandbox that strips secrets from the image config before publishing. Tools like TruffleHog can scan layers, but they must run as a mandatory gate, not an optional lint step. The sandbox should also enforce that any `RUN` command that expands environment variables never writes them into the image history.

Third, every agent action, pull, push, merge, deploy, needs an immutable audit log. The log should record who invoked the action, which token was used, and the exact git commit that changed. Auditable logs turn a silent breach into a forensic trail that can be acted upon in minutes.

Finally, treat the registry itself as a critical asset. Public projects should never contain images that embed credentials. If a public project is required for distribution, enforce a policy that strips all secrets before the image is pushed. Regular scans of public registries for accidental exposure should be automated.

## What PMs Must Do Today

PMs should audit every PAT their platform issues, verify scopes, set expirations, and rotate any token older than six months. They must also make secret scanning a CI gate, integrating TruffleHog or a comparable scanner into every build pipeline and failing the build on any detection.

Deploy a sandboxed build environment that discards build‑time environment variables from the final image config. Expose an immutable action log to customers so they can see which token performed which git operation and when.

Educate engineering teams that a Docker image is more than a filesystem; its metadata can leak credentials forever. Treat these steps as product features to create a moat that is hard for competitors to copy.

## The Bigger Picture

Baseten’s breach is a wake‑up call that the AI platform stack is only as strong as its weakest dev‑ops link. The industry has been busy building larger models, but the real competitive advantage will soon be measured in how safely those models can be delivered.

Platforms that embed token hygiene, zero‑trust sandboxes and auditable logs will attract the most demanding customers and command premium pricing. They also reduce the risk of catastrophic supply‑chain failures.

The next wave of AI product strategy will be decided not by model size but by supply‑chain resilience. PMs who ignore this risk are betting on a house of cards that can collapse with a single leaked token.

**Takeaway:** make token hygiene, sandboxed builds and immutable logs core product capabilities today, or watch your platform become the next headline on Hacker News. Investing now prevents costly incidents and protects your reputation.
