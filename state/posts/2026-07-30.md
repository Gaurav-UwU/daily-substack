## The surprise hidden in a settings page

When the headline reads *GPT‑5.6 hits a 3x boost on ARC‑AGI‑3*, most engineers picture a larger model or a new training dataset. The reality was a pair of API switches that most customers never touched. OpenAI’s announcement showed that a modest change to **compaction** and **reasoning retention** can rewrite the performance curve.

The two knobs are not new concepts; they are parameters that control how the model trades raw token capacity for tighter internal representations and how much of its chain‑of‑thought is preserved across calls. Turning them on simultaneously pushed the benchmark score threefold without any change to the underlying weights.

## Compaction: Making the same brain smaller, not weaker

Compaction asks the model to squeeze information into fewer dimensions before it emits an answer. Think of it as a more aggressive quantization that still respects the original distribution. The result is less noise, faster inference, and, counterintuitively, more consistent reasoning because the model can focus on the core signal.

From a product perspective, compaction is a cost lever. It reduces compute per token, which translates directly into lower cloud bills. For a SaaS offering that bills per request, the margin improvement can be double‑digit without touching pricing.

## Reasoning retention: Keeping the thread alive

Reasoning retention tells the service to cache intermediate steps of a chain‑of‑thought and reuse them when the same logical pattern reappears. The model therefore avoids re‑deriving the same sub‑proofs, saving both time and error surface.

The practical upshot is higher accuracy on tasks that require multi‑step deduction, exactly the kind of problems ARC‑AGI‑3 stresses. Builders who enable this flag see fewer hallucinations and more deterministic outputs, which is a premium feature for enterprise customers.

## Scaling is no longer the only lever

The industry narrative has long been “bigger is better.” GPT‑5.6’s jump shows that the marginal return on adding parameters is now dwarfed by gains from smarter execution. When a 3x boost comes from configuration, the opportunity cost of chasing a next‑generation model rises sharply.

For product teams, this shifts the roadmap. Instead of allocating headcount to model training pipelines, the focus moves to exposing and documenting these hidden settings. The real moat becomes the ability to tune them for specific domains.

## A product lens on the new optimization lever

Three strategic implications follow. First, **moats become configurational**: competitors can copy the architecture but not the tuned settings without the same data. Second, **distribution channels shift**: API‑first products can differentiate by offering pre‑tuned bundles for verticals like legal or finance. Third, **unit economics improve**: lower compute per call means higher throughput at the same hardware budget.

These dynamics echo classic software optimization: a well‑tuned compiler can make code run faster than a newer processor. The AI equivalent is a well‑tuned inference stack.
