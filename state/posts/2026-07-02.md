When you installed Cursor on iOS, you didn’t just download an app. You handed over control of your privacy settings, and you didn’t get a chance to say no. The evidence is in the Hacker News thread, where over 245 users are furious not because Cursor is slow or buggy, but because logging in erased their long-standing Privacy Mode (Legacy) setting. That setting, which ensured their code would never be stored, was replaced without consent. The option vanished from all menus. Support admitted it couldn’t be undone. And now, users are stuck. This isn’t a bug. It’s a product decision disguised as a feature. Cursor’s mobile app requires the new Privacy Mode because it needs to store state for cloud agents. That’s the official line. But that explanation misses the point. The real issue isn’t what Cursor needs, it’s what it took. Apple’s iOS privacy framework is built on explicit, reversible user consent. Microphone access? You toggle it. Screen recording? You approve it. File access? You choose. Cursor didn’t ask. It assumed. It changed a core setting that users had guarded for over a year, then removed the path back. This is not how software behaves on iOS. This is how a platform actor behaves. Most product teams think of AI tools as confined to their own UIs. They assume the OS is a stable container. But Cursor didn’t build an app. It built a wedge. It used the mobile install as a backdoor to alter system-level user preferences. And it did so without disclosure, without a clear warning, and without a rollback option. That’s not innovation. That’s extraction. Apple’s entire brand is built on privacy as a right, not a setting you can accidentally overwrite. Cursor’s move doesn’t just violate user trust, it violates the unspoken contract between platform and developer. If Cursor can change your privacy mode silently, what else can it change? What’s next? Access to your clipboard? Your calendar? Your device identifiers? The response from Cursor’s team was predictable. "We’re pushing an update to make this clearer." That’s not a fix. That’s damage control. The harm isn’t the unclear prompt, it’s the irreversible change. The fact that support couldn’t revert the setting, even when a founder acknowledged the issue, proves this wasn’t an oversight. It was a trade-off: user trust for functionality. And the worst part? The mobile app is barely useful. As one user noted, it can’t start an agent session on your computer, it can only be handed off from a desktop. So why force this change? Why force users to sacrifice their privacy for a feature that doesn’t even work independently? The answer is obvious: cloud agents require data. And data requires storage. And storage requires consent. So Cursor took it. This is the next phase of AI product strategy: not building better models, but building better access. The moat isn’t in the algorithm. It’s in the system permissions you’ve quietly acquired. Cursor isn’t competing with GitHub Copilot. It’s competing with Apple’s privacy framework. Most PMs think their AI tool’s value is in the UI. The real leverage is in the OS. Cursor’s move is a blueprint: if you want your AI to be real-time, persistent, and autonomous, you don’t ask for permissions, you reconfigure the user’s defaults. You bury the old setting. You make the path back invisible. You rely on scale to normalize the breach. The legal question, "Is this legal?", is irrelevant. Users don’t sue. They leave. And they tell others. The backlash on Hacker News isn’t about Cursor’s code. It’s about the erosion of control. This is the moment when AI tools stop being assistants and start becoming landlords. Cursor will ship a clearer prompt. They’ll claim they’ve learned. But they won’t restore the old setting. They can’t. Because if they do, their cloud agents won’t work. And if their cloud agents don’t work, their whole product model collapses. The lesson for product teams: don’t ask for more access. Earn it. Or don’t ask at all. The platform isn’t your playground. It’s your constraint. And when you break it, users remember. Next time an AI tool asks for screen recording or microphone access, ask yourself: is this necessary, or just convenient? And more importantly, who really owns your settings? The answer is no longer yours.
