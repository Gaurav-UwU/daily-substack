## Why the AI arms race is about data, not compute

When I asked my Slack bot to file a bug, it opened a GitHub issue, attached screenshots, and posted the link back to the channel without me touching a browser. The same moment felt familiar across the enterprise AI hype train, Notion AI, Jasper Chat, Microsoft Copilot, all promising to turn a prompt into a finished task. What most of them share is a single, massive language model that powers every customer.

The model size race has been the headline for years. Bigger models win benchmarks, attract headlines, and justify higher pricing. Yet the marginal gain from adding another billion parameters is shrinking, while the cost of running them at scale climbs.

What the market is missing is the lever that actually changes unit economics: the ability to turn a firm’s own documents, Slack threads, and CRM records into a living, queryable brain. That lever flips the advantage from the provider’s compute budget to the customer’s data moat.

## Almanac’s approach: a private, always‑on knowledge agent

Almanac describes itself as "the agent with a second brain" that lives in its own computer, signed into every tool you connect. It can be summoned from iMessage or Slack, and it replies when a task is done, just like a human assistant.

A concrete interaction reads like a conversation: you tell Almanac to "go through the customer slack, file any new bugs with repro steps," and it replies "done, filed #412 and #413 with screenshots and repro steps, linked the slack threads." The same agent later answers "what did we promise Vercel on pricing?" by pulling the March pricing email and the latest support ticket, then sends the answer back to the channel.

Behind the scenes is a wiki that continuously updates itself. Every piece of information, a pricing confirmation email, a CSV export failure, a quarterly business review note, is compiled into a page that links back to its source. If the page is wrong, you edit it and the agent learns from the correction.

Security is baked in: only the accounts you explicitly connect are readable, each connection is visible in the UI, and you can revoke at any time. Personal inboxes stay private; the shared wiki only contains the distilled decision, not the raw messages.

## The strategic shift: from model size to company‑specific moat

The real competitive advantage is no longer the number of parameters but the ability to ingest, index, and keep fresh a firm’s proprietary data. Once a company has a continuously refreshed knowledge base, any external model that cannot see that data is forced to operate on stale or incomplete context.

That creates a friction point for incumbents. A vendor that only offers a generic LLM must now charge for the plumbing that keeps the private wiki alive, or risk being bypassed by an in‑house solution that already knows the business.

Data‑governance becomes a pricing lever. Companies will compare offers based on how many "knowledge‑base minutes" they get, not just on API token volume. Lock‑in will be measured by how many internal processes are already wired into the agent’s always‑on computer.

Running Claude or Codex on a laptop gives you the same model, but the context disappears when the lid closes. Almanac’s separate machine stays signed in, watches the inbox, updates the wiki, and reports back, delivering value even when the user is offline.

## What product leaders must do today

Start Monday by mapping every internal data silo, Slack channels, Gmail folders, CRM records, GitHub issues, and rank them by how often a decision depends on them. Identify the integration points that a knowledge agent would need to stay current.

Evaluate vendors on three criteria: (1) does the agent run on a dedicated always‑on computer, (2) can it continuously pull from your connected tools, and (3) does it expose a transparent audit trail for each piece of knowledge.

If the integration cost outweighs the expected productivity lift, consider building a minimal pipeline that mirrors Almanac’s wiki approach. Otherwise, negotiate contracts that price the private knowledge layer separately from the underlying model.

In the next twelve months I expect most enterprise AI deals to be structured around "knowledge‑base minutes" rather than raw token counts. The companies that lock in a living, company‑specific brain will command the most leverage, while those that bet on bigger models alone will find their moat evaporating.

**Takeaway:** The next moat is a private, continuously updated LLM that knows your company, not a larger generic model.
