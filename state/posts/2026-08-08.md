## The statistic that should make us uneasy

In a simple browser game that asked players to approve or deny AI-generated shell commands, the average participant let a threat through every third time. Across more than 40,000 runs and 409,000 individual decisions the mean accuracy settled at 66.3 percent.

That number is not a footnote. Roughly a third of the sessions ended with a negative score because the penalties from approved threats outweighed the gains from blocked safe commands. Only 35.2 percent of players caught every threat, and just 20.8 percent managed to do so without blocking more than one in five harmless commands. The rest either blocked everything or, in a striking 7 percent of cases, approved every prompt, effectively turning the safety layer into a fast-track button.

## Human approval is not a reliable backstop

The game split threats into four categories. Obviously destructive commands like `rm -rf /` were caught 88.3 percent of the time, but exfiltration-style attacks such as `curl` to unknown APIs slipped through 66.6 percent of the time. Scope-violation commands that read credential files were missed 65 percent of the time, and persistent mutation attacks like crontab injection were missed nearly a quarter of the time.

Anthropic has already warned that permission fatigue is real: the more approvals a user sees, the less attention each receives. The game reproduced that effect; miss rates climbed as the session progressed, suggesting that even a brief period of time pressure can erode vigilance. In real product environments, the pressure to ship quickly can be far more intense than a five-minute game, so the degradation is likely to be worse.

## Familiar scripts become Trojan horses

The single most-missed command was `npm run analyze`, approved 64.7 percent of the time. On its surface the command is harmless, it runs a bundle analyzer defined in `package.json`. The twist is that the script can be hijacked to exfiltrate data, as the game’s history log demonstrated with a hidden `curl` call.

Three npm scripts appeared in the top-ten missed threats: `npm run analyze` (64.7 percent), `npm run setup` (48 percent) and `npm run deploy` (44.9 percent). Together they were approved more than half the time, whereas the average exfiltration-style attack was blocked only 28.4 percent of the time. Hiding a payload behind a familiar name roughly doubled its success rate, even when the suspicious code was displayed just above the permission prompt.

## The permission model is fundamentally brittle

As one Hacker News commenter observed, asking users to validate commands that are “nearly always safe” but can become dangerous after a file edit is “absolutely bonkers.” The model assumes that a human can infer the intent of a command without full context, an assumption that collapses once a repository is compromised.

For product teams, the implication is clear: a binary approve/deny UI does not scale to the complexity of modern codebases. When an AI agent can modify `package.json`, inject files into `node_modules`, or alter a crontab, the surface-level command no longer conveys the risk. Relying on a human as the last line of defense creates a false sense of security and concentrates risk in a single, fatigue-prone decision point.

## What a PM should do on Monday

First, treat AI-generated commands as mutable assets rather than static requests. Build a provenance layer that records every file change an agent makes before it proposes a command, and surface that diff to the reviewer. Second, replace the approve/deny toggle with risk scores that auto-reject high-severity categories unless a senior engineer explicitly overrides them. Third, limit the frequency of permission prompts by bundling low-risk actions into a single, audited batch.

Finally, measure permission fatigue as a product metric. Track the proportion of approvals that later turn out to be threats, and adjust the UI or automation thresholds when the error rate climbs above a pre-defined ceiling. If the data shows that one in three threats still slip through, the system is not ready for production use.

The takeaway is simple: human judgment is not the moat we thought it was. Building AI-enabled products without a deeper, context-aware safety net invites exactly the kind of slip-through that the Scale X game exposed.
